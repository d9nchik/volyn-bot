Telegram-бот «Світло Волинь · 3.1»

Бот надсилає українською графіки відключень для підчерги 3.1.
Розгорнуто в GitHub Actions 24.11.2026. Перший хмарний запуск успішний.
Репозиторій: https://github.com/d9nchik/volyn-bot
Запуски: https://github.com/d9nchik/volyn-bot/actions

Як працює
- Кожні 15 хвилин перевіряє графіки на сьогодні й завтра через публічний API.
- Зіставляє зображення із записом архіву, щоб підтвердити дату графіка.
- Читає кольорові комірки підчерги 3.1 та надсилає години відключень.
- Повідомляє про новий графік або зміну інтервалів; показує попередній розклад.
- Нагадує під час перевірки, якщо до відключення залишилося до 30 хвилин.
- Повідомляє про недоступне джерело або невідомий формат графіка.
- Після відновлення доступу повідомляє, що отримання графіка відновлено.

Розклад перевірок
Workflow запускається на 7, 22, 37 та 52 хвилині кожної години (UTC).
Час у повідомленнях указано за Києвом. Комп’ютер користувача може бути вимкнений.
Для ручної перевірки: Actions → Check Volyn 3.1 → Run workflow.
Перед кожною перевіркою виконуються автоматичні тести.

Налаштування власного бота
1. Створіть бота через /newbot в офіційному Telegram-боті @BotFather.
2. Відкрийте свого бота й надішліть /start.
3. Створіть публічний репозиторій GitHub із файлами проєкту, включно з .github.
4. Виконайте python3 setup_chat.py та введіть токен у прихований запит.
   Скрипт покаже chat_id особистого чату. Бот має працювати без webhook.
5. У Settings → Secrets and variables → Actions додайте:
   TELEGRAM_BOT_TOKEN — токен від BotFather;
   TELEGRAM_CHAT_ID — ID вашого особистого чату.
6. Запустіть workflow вручну та перевірте отримання повідомлення в Telegram.

Секрети
У GitHub токен і chat_id зберігаються в Actions Secrets.
Локальний .env і каталог .state виключено з git через .gitignore.
.env.example містить порожній шаблон налаштувань.
Сам bot.py читає змінні середовища; автоматичного завантаження .env немає.
Не публікуйте заповнений .env і не додавайте токен до коду або журналів.

Вартість
Стандартні GitHub-hosted runners безкоштовні для публічних репозиторіїв:
https://docs.github.com/en/actions/concepts/billing-and-usage
У приватному репозиторії витрачається місячна квота облікового запису.
За такого розкладу буде близько 2880 запусків за 30 днів.
Звичайні повідомлення Telegram безкоштовні:
https://core.telegram.org/bots/faq
Розпізнавання не використовує AI або платні API; браузер і обхід капчі не потрібні.

Обмеження
GitHub може затримувати або пропускати запуски. Нагадування не гарантоване
рівно за 30 хвилин і може не надійти до початку відключення.
Бот показує опублікований графік, а не фактичну наявність електропостачання.
Якщо джерело недоступне, попередній графік може бути застарілим.
GitHub вимикає розклад публічного репозиторію після 60 днів без активності.
Періодично перевіряйте Actions і за потреби вмикайте workflow знову:
https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

Стан зберігається в Actions cache. Після очищення або витіснення кешу можливе
повторне надсилання графіка чи нагадування. Одночасні перевірки виконуються по черзі.
Парсер перевіряє поточний шаблон PNG розміром 1750×2250: палітру та сітку.
Зміна шаблону потребуватиме оновлення парсера. Перестановку підписів зі збереженням
сітки парсер не визначає. Тестове зображення додано для ручного порівняння.
Доступ до джерела та надсилання в Telegram перевірено з GitHub Actions.

Локальна перевірка
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python bot.py --dry-run

Режим --dry-run читає джерело, але не надсилає повідомлень і не змінює стану.
Перевірка без мережі:
.venv/bin/python bot.py --image tests/fixtures/2026-11-24.png

У тестовому графіку на 24.11.2026 для підчерги 3.1 указано 08:00–11:00.
Це зафіксований приклад для тестів, а не поточний прогноз.
